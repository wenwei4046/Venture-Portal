`reconciles = Math.abs(437,000 − 296,000.01) < 1` evaluates **FALSE**.

### Root cause decomposition

The retained-earnings figure (−136,999.99) is inflated negative by **RM 150,000** because `fetchCashflowBuckets` counts ALL paid debit payment_vouchers as IS expenses — including two loan-disbursement PVs that are balance-sheet transactions, not P&L items.

| PV id | voucher_type | pv_ref_type | RM | JE? | JE segment | Expected segment | Impact |
|-------|--------------|-------------|------|-----|------------|-----------------|--------|
| `d4206ded-cee6-41b5-b142-3581bc8908a1` | other | loan | 50,000 | **No** | — (defaults to unallocated in cashflow) | treasury | Counts as generalExpense; overstates IS cost by RM 50k |
| `2a0e4c03-a403-44bb-af0b-fcf3ec0cbd39` | other | loan | 100,000 | Yes | **corporate** ← wrong | treasury | Counts as generalExpense; overstates IS cost by RM 100k; wrong segment attribution |

Removing both from the cost bucket:
- Corrected YTD cost: RM 151,999.99 − RM 150,000 = **RM 1,999.99** (two legitimate expense PVs)
- Corrected retained earnings: RM 15,000 − RM 1,999.99 = **RM 13,000.01**
- Corrected total L+E: RM 433,000 + RM 13,000.01 = **RM 446,000.01**
- Residual drift: RM 437,000 − RM 446,000.01 = **−RM 9,000.01**

The residual −RM 9,000.01 (assets < L+E) is consistent with an opening bank balance not fully reflected in journal entries (seed/pre-system data). No further investigation needed until Phase 4 opens-balance migration is planned.

**Primary fix:** mig 217 trigger is missing a rule: when `reference_type = 'payment_voucher'` and `pv.reference_type = 'loan'`, derive segment = `treasury`. A secondary code-layer fix is also needed in `fetchCashflowBuckets` to exclude `treasury`-segment PVs from IS expense buckets (loan disbursements are asset movements, not P&L costs).

## Remediation plan

### 1. Migration fix (mig 234 — included in this PR)

`supabase/migrations/20260101000234_extend_derive_journal_segment.sql`:

- Adds rule to `derive_journal_segment()`: when `reference_type = 'payment_voucher'` and `pv.reference_type = 'loan'` → return `treasury`
- UPDATEs the existing wrong-segment JE for PV `2a0e4c03` from `corporate` → `treasury`
- Orphaned PV `d4206ded` (no JE): the economic event is already captured by the sibling `loan` JE (reference_type=`loan`, same date/amount). Creating a second PV-level JE would duplicate the posting. **Manual action required:** confirm with Finance whether this PV should be voided or left as-is with no separate PV JE. Flag: no GL harm because the loan JE is present; only the IS cashflow bucket misreads it as an expense.

### 2. Code fix (separate PR — not in this PR)

`src/lib/cfo-reports.ts` → `fetchCashflowBuckets`:  
Filter out payment vouchers whose GL segment is `treasury` from the expense/dept-outflow aggregation. Loan disbursements, fund-source deposits, and loan repayments are balance-sheet movements — the cashflow report's bucket-B/C should only accumulate operational expenditure.
