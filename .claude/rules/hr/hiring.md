# HR tab — Hiring

Hiring › Requests, Insights and the Talent Bank — `src/app/(portal)/hiring/`, `src/lib/hiring/`. DESIGN.md › "Hiring › Requests" is the visual spec; how a page and its writes are gated is `../portal-wide/permissions.md`.

Read this before changing anything it covers, and again in every full scan of such a change (a review, QA, an E2E audit) — CLAUDE.md › Rules by tab. New decisions are added here, dated, never to CLAUDE.md.

**HIRING (2026-10-11, the HR revamp's second package — README §11–13 of `.design/hr-r2/handoff`, the prototype `Revenue App.dc.html` winning over the README; migs `20261011080000`, `20261011080100`, `20261011080200`).** HR's sidebar section **V. HIRING** (tone clay, between People and Admin): Requests (`/hiring/requests`), then Insights and Talent Bank. The old shell lists it as *Hiring Requests* in a Hiring section. Every page is on the white sheet (`lib/sheet-routes.ts` `/hiring`).

- **Who may.** The page asks the TAB first (`requirePage('/hiring/requests')`, tab `hr.hiring_requests`; Insights `hr.hiring_insights`, the Talent Bank `hr.talent_bank`), then `requirePermission('hiring')`. Each button asks its own cell: **View** reads; **Create** files a request ("+ New request"), adds a candidate, saves or invites a talent; **Approve** decides — Acknowledge, Request more info, Decline, the owner, Mark filled, Cancel request, Reopen; **Edit** changes Form settings, the hiring sources, the candidate fields, a candidate's details and status, a talent's notes and résumé, and removes a talent. *Assisted by* asks Edit or Approve. The Form settings tab shows only to Edit.
- **Tables** `hiring_requests` (`HR-001`… from `hiring_request_no_seq`; status `submitted` · `needs_info` · `acknowledged` · `filled` · `cancelled` · `declined`; `source` portal / guest; the form AS IT WAS SENT in `fields`, the answers in `answers` — editing Form settings changes new requests only), `hiring_request_events` (the trail), `hiring_candidates`, `hiring_form_fields`, `hiring_sources`, `hiring_candidate_fields`, `hiring_talents` (`T-001`…, removed softly) and `hiring_talent_events`. RLS on, NO policy, nothing granted: every read and write is a DEFINER function asking `has_any_action(ARRAY['hiring.…'])` (`IS NOT TRUE` → 42501, a refusal in words → 22023). Each table is `audit_register`ed under People (read `{hiring}`; the two trails mode none).
- **Functions** — reader `hiring_board()` (everything the pages draw: fields, sources with how often used, candidate fields, people working here today, requests with candidates and trails, talents, `me`) and `hiring_file_path(kind, id)`, both STABLE and on `READS_WHILE_VIEWING_AS`; writers `hiring_submit`, `hiring_acknowledge`, `hiring_request_info`, `hiring_decline`, `hiring_set_owner`, `hiring_set_assist`, `hiring_fill`, `hiring_cancel`, `hiring_reopen`, `hiring_candidate_add` / `_edit` / `_stage`, `hiring_save_form_fields`, `hiring_save_candidate_fields`, `hiring_source_add` / `_set_active` / `_remove`, `hiring_talent_save` / `_invite` / `_update` / `_remove`, `hiring_resume_downloaded`. `hiring_file_of` (writes while reading) is closed to `authenticated` since `080100`.
- **The words are the handoff's**, written by the database where they are a refusal: *Fill in Department, Headcount, … .* (the form's required fields, in order), *Pick the owner first.*, *Write what you need from the requester.*, *Give a reason for declining.*, *Choose who was hired, then Mark filled*, *Pick where you found them, then Mark filled*. The trail's steps: Submitted (the requester names it) · Submitted via guest link · Acknowledged (the OWNER names it, *Takes responsibility for this hire · note*) · More info requested · Declined · Owner changed (*A → B*) · Assisted by / Assist removed · Candidate added / edited / status · Résumé downloaded · Saved to Talent Bank · Filled (*Hired: X · via Jobstreet · cost RM 450 · note*) · Cancelled (*No longer needed* unless a note) · Reopened. The major ones (a filled dot, STATUS) are `view.ts` `MAJOR_EVENTS`.
- **The owner is somebody in the HR department working here today** (department named `HR`); *Assisted by* is HR and anyone titled leader / manager / director, never the owner. *Requested by* is anybody working here today.
- **A declined request may be reconsidered** (mig `080200`): Acknowledge or Request more info from the Declined filter reopens it; it is not declined twice. Mark filled names THIS request's candidates who were not turned down, and an ACTIVE source; the hired become *Hired*. A used source is turned off, never removed. Position and Department are core: renamed, never removed.
- **Files**: the private bucket `hiring-files` (10 MB; PDF, Word, PNG / JPEG / WebP) — `resumes/<candidate|talent id>/…`, `attachments/<request>/…` (uploads ask Create or Edit), `guest/…` (the guest link's, written by the service role). A file is opened by a signed link made at the press (10 minutes); a candidate's download is on the trail. The résumé drawer frames a PDF, shows an image, and says a Word document opens in Word.
- **The guest link** (the rooms fork's guest page asks these; never a browser): `hiring_guest_form() RETURNS jsonb` — the current form, `[{id, label, type, options, required, core}]` — and `hiring_file_guest_request(p_company text, p_department text, p_name text, p_phone text, p_answers jsonb, p_attachment_path text DEFAULT NULL, p_attachment_name text DEFAULT NULL) RETURNS text` (the new request's id; the attachment already stored under `guest/`). Both are the **service role's alone** — revoked from PUBLIC, anon and authenticated — called after the guest page has checked its link. A guest never edits or cancels a request (user 2026-10-11: HQ does not give guests edit).
- **Other callers** (the HR phone app) read through `lib/hiring/board.ts` `loadHiringBoard()` and draw with `lib/hiring/view.ts` (`requestSummary`, `hrOwners`, `activeSources`, `STATUS`, `STAGE`); they write through `lib/hiring/actions.ts`.
- **Decided while building (the user asleep; asked in `.design/hr-r2/questions-hiring.md`):** *Preview form* opens the New request drawer as a requester sees it; a toast does not say *· X is notified* (nothing notifies yet); the Listing's footnote drops *Sample requests.*; Department's choices start as the real departments; *Open in Talent Bank* shows once the Talent Bank page is live.
- **Tests:** `lib/hiring/view.test.ts`, `parse.test.ts`, `files.test.ts`, the components' `RequestInbox` / `RequestListing` / `NewRequestDrawer` tests (the handoff's sample data is `src/test/hiring-board.ts`), PGlite `tests/member-sql/validate-hiring.mjs`. An E2E on prod names its rows "E2E …" and deletes them after, then sets the two sequences back while the tables are empty.
