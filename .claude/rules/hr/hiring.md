# HR tab — Hiring

Hiring › Requests, Insights and the Talent Bank — `src/app/(portal)/hiring/`, `src/lib/hiring/`. DESIGN.md › "Hiring › Requests" is the visual spec; how a page and its writes are gated is `../portal-wide/permissions.md`.

Read this before changing anything it covers, and again in every full scan of such a change (a review, QA, an E2E audit) — CLAUDE.md › Rules by tab. New decisions are added here, dated, never to CLAUDE.md.

**HIRING (2026-10-11, the HR revamp's second package — README §11–13 of `.design/hr-r2/handoff`, the prototype `Revenue App.dc.html` winning over the README; migs `20261011080000`, `20261011080100`, `20261011080200`).** HR's sidebar section **V. HIRING** (tone clay, between People and Admin): Requests (`/hiring/requests`), then Insights and Talent Bank. The old shell lists it as *Hiring Requests* in a Hiring section. Every page is on the white sheet (`lib/sheet-routes.ts` `/hiring`).

- **Who may.** The page asks the TAB first (`requirePage('/hiring/requests')`, tab `hr.hiring_requests`; Insights `hr.hiring_insights`, the Talent Bank `hr.talent_bank`), then `requirePermission('hiring')`. Each button asks its own cell: **View** reads; **Create** files a request ("+ New request"), adds a candidate, saves or invites a talent; **Approve** decides — Acknowledge, Request more info, Decline, the owner, Mark filled, Cancel request, Reopen; **Edit** changes Form settings, the hiring sources, the candidate fields, a candidate's details and status, a talent's notes, replaces and removes files, names a file type, and removes a talent (files: FILES below). *Assisted by* asks Edit or Approve. The Form settings tab shows only to Edit.
- **Tables** `hiring_requests` (`HR-001`… from `hiring_request_no_seq`; status `submitted` · `needs_info` · `acknowledged` · `filled` · `cancelled` · `declined`; `source` portal / guest; the form AS IT WAS SENT in `fields`, the answers in `answers` — editing Form settings changes new requests only), `hiring_request_events` (the trail), `hiring_candidates`, `hiring_form_fields`, `hiring_sources`, `hiring_candidate_fields`, `hiring_talents` (`T-001`…, removed softly) and `hiring_talent_events`. RLS on, NO policy, nothing granted: every read and write is a DEFINER function asking `has_any_action(ARRAY['hiring.…'])` (`IS NOT TRUE` → 42501, a refusal in words → 22023). Each table is `audit_register`ed under People (read `{hiring}`; the two trails mode none).
- **Functions** — reader `hiring_board()` (everything the pages draw: fields, sources with how often used, candidate fields, people working here today, requests with candidates and trails, talents, `me`) and `hiring_file_path(kind, id)`, both STABLE and on `READS_WHILE_VIEWING_AS`; writers `hiring_submit`, `hiring_acknowledge`, `hiring_request_info`, `hiring_decline`, `hiring_set_owner`, `hiring_set_assist`, `hiring_fill`, `hiring_cancel`, `hiring_reopen`, `hiring_candidate_add` / `_edit` / `_stage`, `hiring_save_form_fields`, `hiring_save_candidate_fields`, `hiring_source_add` / `_set_active` / `_remove`, `hiring_talent_save` / `_invite` / `_update` / `_remove`, `hiring_resume_downloaded`; since `160000` the files' `hiring_files_add`, `hiring_file_replace`, `hiring_file_remove`, `hiring_file_type_add`, `hiring_file_downloaded` and `hiring_orphan_files` (FILES below). `hiring_file_of` (writes while reading) was closed to `authenticated` in `080100` and dropped in `160000`.
- **The words are the handoff's**, written by the database where they are a refusal: *Fill in Department, Headcount, … .* (the form's required fields, in order), *Pick the owner first.*, *Write what you need from the requester.*, *Give a reason for declining.*, *Choose who was hired, then Mark filled*, *Pick where you found them, then Mark filled*. The trail's steps: Submitted (the requester names it) · Submitted via guest link · Acknowledged (the OWNER names it, *Takes responsibility for this hire · note*) · More info requested · Declined · Owner changed (*A → B*) · Assisted by / Assist removed · Candidate added / edited / status · Résumé downloaded · Saved to Talent Bank · Filled (*Hired: X · via Jobstreet · cost RM 450 · note*) · Cancelled (*No longer needed* unless a note) · Reopened. The major ones (a filled dot, STATUS) are `view.ts` `MAJOR_EVENTS`.
- **The owner is somebody in the HR department working here today** (department named `HR`); *Assisted by* is HR and anyone titled leader / manager / director, never the owner. *Requested by* is anybody working here today.
- **A declined request may be reconsidered** (mig `080200`): Acknowledge or Request more info from the Declined filter reopens it; it is not declined twice. Mark filled names THIS request's candidates who were not turned down, and an ACTIVE source; the hired become *Hired*. A used source is turned off, never removed. Position and Department are core: renamed, never removed.
- **Files**: the private bucket `hiring-files` (10 MB; PDF, Word, PNG / JPEG / WebP) — `files/<uuid>/…` (a candidate's or a talent's, since `160000`; older ones `resumes/<uuid>/…`), `attachments/<request>/…` (uploads ask Create or Edit), `guest/<code>/<uuid>.<ext>` (the guest link's: written by the guest's browser with the PUBLISHABLE key under the storage policy `guest_link_uploads` — exactly that name, the link's current code, Request manpower open, at most 40 files an hour; never the service role — `rooms.md`). A file is opened by a signed link made at the press (10 minutes); a candidate's download is on the trail. The résumé drawer frames a PDF, shows an image, and says a Word document opens in Word.
- **The guest link's door** (asked only by the guest link's own functions; never a browser): `hiring_guest_form() RETURNS jsonb` — the current form, `[{id, label, type, options, required, core}]` — and `hiring_file_guest_request(p_company text, p_department text, p_name text, p_phone text, p_answers jsonb, p_attachment_path text DEFAULT NULL, p_attachment_name text DEFAULT NULL) RETURNS text` (the new request's id; the attachment already stored under `guest/`). Both are revoked from PUBLIC, anon and authenticated (the service role keeps EXECUTE and never calls them). **What shipped** (mig `20261011092000`; corrected here 2026-10-11 after the security review, L9 — this bullet used to say the service role called them): the way in is `guest_link_hire(code, subsidiary, name, answers, path, file)` — SECURITY DEFINER, owned by postgres, granted to anon BY NAME — which checks the link's code (on, the CURRENT code, Request manpower open), refuses past 20 guest requests an hour (mig `20261011120000`), checks the company is on the link's list, the name, and that the attachment is `guest/<current code>/<uuid>.<ext>` and really in the bucket, and only then calls `hiring_file_guest_request`; `guest_link_page` hands the form out through `hiring_guest_form()`. No service role anywhere on that path (`rooms.md` › Request manpower). A guest never edits or cancels a request (user 2026-10-11: HQ does not give guests edit).
- **Other callers** (the HR phone app) read through `lib/hiring/board.ts` `loadHiringBoard()` and draw with `lib/hiring/view.ts` (`requestSummary`, `hrOwners`, `activeSources`, `STATUS`, `STAGE`); they write through `lib/hiring/actions.ts`.
- **Decided while building (the user asleep; asked in `.design/hr-r2/questions-hiring.md`):** *Preview form* opens the New request drawer as a requester sees it; a toast does not say *· X is notified* (nothing notifies yet); the Listing's footnote drops *Sample requests.*; Department's choices start as the real departments; Insights and the Talent Bank drop the prototype's *Sample data.* / *Sample talent.*; Insights counts *Info requested* as open (its days so far run on).
- **INSIGHTS AND THE TALENT BANK (2026-10-11, README §12–13).** `/hiring/insights` (tab `hr.hiring_insights`, View only — nothing on it writes) and `/hiring/talent` + `/hiring/talent/[id]` (tab `hr.talent_bank`: View reads, Create adds and invites (and adds files), Edit edits notes, replaces and removes files, removes). Insights is `lib/hiring/insights.ts` (`insightsOf`, `insightFacts`), the handoff's insVals: a period is this month (the OFFICE's, handed in by the page), a month of the last twelve or all time; a request is in it when submitted or filled in it; its days come from the request's own `acknowledged_at` / `filled_at` / `closed_at` (office days); the change is on the month before (People hired up is good, days and cost down are good); departments are the Department field's first parts, then any a request names. The Talent Bank's status: *Interviewing · HR-…* while the talent is a not-turned-down candidate on an open request, else *Available*; a removed talent leaves the bank and its candidates are no longer linked (`talentId` null). A request page's candidate in the bank offers *Open in Talent Bank*.

- **FILES (2026-10-11, the user's answers after round 2; mig `20261011160000`, DESIGN.md › "Hiring files").** The user: "they can upload different files as well, then name the file type" — a Talent Bank person and a request's candidate keep several files, each with a FILE TYPE; a candidate kept in the bank brings them all; the Talent Bank is **never emptied by itself** (no retention period — HR removes people); a file taken off a record is **really deleted** (the review's L7, PDPA).
  - **Tables** `hiring_file_types` (Résumé = `builtin 'resume'`, IC, Certificate; HR adds more — the same name in any case is the same type; since `210000` renamed and turned off in Form settings, below) and `hiring_files` (one row per file on ONE candidate or ONE talent: its type, `path` in `hiring-files`, the name it came with, who added it, up to 20 each). RLS on, no policy, nothing granted, `audit_register`ed under People. The résumé columns (`resume_path`, `resume_name`) became Résumé rows and were dropped.
  - **Two rows may name one object**: Move to Talent Bank copies the candidate's rows to the talent, Invite to interview the talent's to the new candidate. An object goes only when NO row names it, nor a request's attachment (`hiring_file_in_use`).
  - **Who may**: Create adds files (with a candidate, a talent, or *+ Add file* — `hiring_files_add`); Edit replaces and removes them and names a new type (`hiring_file_type_add`, from the type picker's *+ Add a new file type…*).
  - **Uploads** go from the browser (`lib/hiring/upload.ts`) straight into the bucket at `files/<uuid>/<name>` under `hiring_files_write` (Create or Edit) — never through a Server Action, whose body stops at 4 MB; the function that files one (`hiring_take_upload`) asks that the object really is there and on nobody's record yet.
  - **Deleting**: `hiring_file_remove`, `hiring_file_replace`, `hiring_candidate_edit(…, p_remove)` and `hiring_talent_remove` take the rows off and answer `{ orphans }` — the objects nobody names any more — and the Server Action deletes them under the caller's own session through the storage policy `hiring_files_delete` (Hiring · Edit, and only an object `hiring_file_in_use` says nobody names: never a file still on a record). A deletion the bucket refuses is SAID (`warning`, *Saved, but the removed file is still in storage…*), never swallowed — the bucket answers a refused delete with nothing deleted, not an error, so `deleteObjects` counts.
  - **Leftovers** — objects nobody names that went in over a day ago (a guest's upload never sent, a window closed before Save, a refused delete): `hiring_orphan_files(p_limit)` (Edit, STABLE) lists them and every file write by an Edit holder clears up to 50 (`sweep`, `lib/hiring/actions.ts`); since `210000` the hourly member-queue cron clears them too (below).
  - **The words**: request trail / History *File added*, *File removed*, *File replaced*, *Résumé replaced*; a candidate's *Résumé downloaded* / *File downloaded*; *Removed from Talent Bank* says *N files deleted*. `hiring_board()` answers `fileTypes` and each candidate's and talent's `files` (`resume` true for the Résumé; the résumé first, then by type, then as added) and still `resumeName`; `hiring_file_path('file', id)` finds any one file, `'candidate'` / `'talent'` their newest résumé.
  - **The parts**: `HiringFiles.tsx` (the type picker, a file row, the files waiting for Save, `sendWaiting`), `FilesDrawer.tsx` (the résumé drawer with a pill per file), the Add / Edit candidate window and *+ Add talent* (files wait for Save; Edit's Remove / Undo apply on Save), the talent page's Files card (each action at once). The HR app draws no files; its *Remove from Talent Bank* deletes them through `removeHiringTalent`.
  - **Tests**: `Candidates.test.tsx`, `TalentPage.test.tsx`, `TalentBankView.test.tsx`, `files.test.ts`, `parse.test.ts`; PGlite `validate-hiring.mjs` (its 160000 part). E2E 2026-10-11 on production's database (the branch on localhost): request HR-001 *E2E Tester* — a candidate with a CV and an IC, Edit (IC off, a certificate on), Move to Talent Bank, *+ Add file* under a new type, Replace, Remove, Remove from Talent Bank, then the candidate's files off; the bucket checked by SQL after each stage (an object two records shared stayed until the last went), then the rows deleted and both sequences set back.

**WHO A REQUEST TELLS (2026-10-11, mig `20261011180000`, `notify_hiring_request`).** A request's step tells the person who asked for it (`requested_by`'s login): *HR acknowledged your request HR-205*, *HR needs more information · HR-205*, *HR declined your request HR-205*, *HR-205 is filled* (*Hired: …*), *HR-205 was cancelled* — never when they took the step themselves; a guest-link requester has no login and hears nothing. A guest-link request tells the holders of the `hiring.guest` topic (Hiring · Approve, kept by the HR app). This is the toast's "· Kar Jun is notified" the build had left out: the notice is real now. Rules: `.claude/rules/portal-wide/pwa.md` › PHONE NOTIFICATIONS.
- **FILE TYPES RENAMED AND TURNED OFF; THE LEFTOVERS EVERY HOUR (2026-10-11, the user's answers on the hiring-files questions; mig `20261011210000`).** The user: "加改名和停用" and "每小时自动清"; one object shared by two records, and Edit candidate's Remove waiting for Save, stay as they are.
  - **File types** are managed in Hiring › Requests › **Form settings** (Edit only, as the tab is), a third card after the hiring sources and drawn like them: each type with its files (`N files`), ✎ to rename in place (Enter or leaving the field keeps it, Esc lets it be — `hiring_file_type_rename`, a name another type has is refused), and **On / Off** (`hiring_file_type_set_active` — `retired_at` / `retired_by` on `hiring_file_types`). **Résumé is built in**: *Built in*, never renamed, never turned off (both refused in the database too). *+ Add type* names a new one.
  - **A type turned off** leaves the picker (`HiringFiles` lists only types that are on); the files already filed under it keep it and show it; a copy made by Move to Talent Bank or Invite to interview keeps it; Replace keeps it; nothing NEW is filed under it (`hiring_attach` refuses: *NRIC is turned off — pick another type.*). Naming it again (*+ Add a new file type…* or *+ Add type*) turns it back on — `hiring_file_type_add` answers that type.
  - **The leftovers every hour**: the member-queue cron (`app/api/member-queue/route.ts`, hourly, the service role — an existing admin.ts caller given this second job, `.claude/rules/portal-wide/permissions.md`) calls `sweepHiringLeftovers` (`lib/hiring/leftovers.ts`, handed the cron's client): `hiring_leftovers(p_limit)` lists objects in `hiring-files` that no record names and that went in over a day ago, at most 200 a run, and the Storage API deletes them. It logs counts only (`Hiring leftovers deleted N of M`; the names are people's files) and answers `hiringLeftovers: { listed, deleted }` in the run's JSON; a failed list is `null` and logged, and never fails the run. `hiring_leftovers` is the service role's alone (revoked from PUBLIC, anon, authenticated); `hiring_orphan_files` (Edit) asks its cell and reads the same list, so HR's on-write clearing goes on.
  - **Tests**: `FormSettings.test.tsx`, `leftovers.test.ts`, `TalentPage.test.tsx` (a type turned off leaves the picker), `parse.test.ts`; PGlite `validate-hiring.mjs` (its 210000 part — Edit only, Résumé refused, a clash refused, the files keep a renamed and a turned-off type, nothing new under it, naming turns it back on, `hiring_leftovers` the service role's and one list with HR's).
